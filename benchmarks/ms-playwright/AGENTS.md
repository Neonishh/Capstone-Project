# CAPSTONE Web C runs

Use the official Playwright Test planner and generator with the assigned shared goal and fixtures. Read [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md) before planning. Record the planner output, generated tests and first execution result under a unique attempt ID.

Map the shared goal to meaningful checks before generation. Generate a separate named Playwright `test()` for each independently verifiable check, with its own necessary setup and assertion. Recreate shared state as needed. Keep dependent actions together when the requirement is a continuous journey, and record named steps and observations for each requirement inside it. Keep native test counts and reviewed requirement counts distinct.

Save expected and observed values, assertion verdicts, execution outcomes and reasons with case IDs and evidence paths. Complete the preconditions, setup, actions and cleanup fields from the actual run. Use `NOT_RECORDED` for unsupported facts. Preserve original results and record healer edits and reruns separately.
